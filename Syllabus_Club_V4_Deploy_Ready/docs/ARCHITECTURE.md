# Syllabus Club V4 — Cloud Architecture

## Design objectives

Preserve the established dashboard and study history while replacing V3's localhost-only SQLite backend with a stateless service suited to Vercel Hobby. Keep notes, sessions and document metadata user-private. Use original issue dates for Current Affairs. Never claim that rule-based relevance is a question probability.

## Runtime architecture

```text
Phone / laptop browser
  │
  ├── Vercel CDN → public/{index,app,data,styles,cloud-bridge}
  │      ├─ localStorage: fast/offline planner cache
  │      └─ Cloud bridge: Supabase email/password Auth
  │
  └── Vercel FastAPI (/api/*)
         ├─ Auth token verification → Supabase /auth/v1/user
         ├─ Owner-email allowlist → OWNER_EMAIL
         ├─ Study snapshot GET/POST → Postgres via Supabase REST
         │     └─ atomic save_study_state() compares revision
         ├─ Private uploads → Supabase Storage
         ├─ Signed private file URLs → Storage API
         ├─ Date-wise articles + user progress → Postgres
         ├─ Optional AI notes → OpenAI, per-user daily quota
         └─ Daily Vercel Cron → PIB RSS + PRS monthly listing
```

## Cloud data

- `study_state` stores the already-existing V3 JSON state per user. A revision number prevents accidental overwrites from two machines.
- `articles` stores official source metadata (owner null) or private owner-uploaded PDFs (owner set).
- `article_progress` stores each owner's read/saved/revision stage without modifying public source metadata.
- `study_documents` maps uploaded Notes-library documents to private Storage objects.
- `ai_usage` protects the owner's API spending with a daily request count. Production scaling beyond one owner may need atomic quota accounting.
- `ingestion_runs` gives visibility into last refresh and ingestion failures.

## Trust boundaries

- **Browser:** Holds a Supabase **public anon key** plus an authenticated session. It cannot access secret keys.
- **API:** Verifies bearer token with Supabase, checks its email matches `OWNER_EMAIL`, and performs record-specific ownership checks. All Vercel API operations with `SUPABASE_SERVICE_ROLE_KEY` are privileged and must never trust a user-supplied owner ID.
- **Postgres RLS:** Rules limit direct user queries to their own rows, with official source rows shared read-only. Only service role writes through the API.
- **File storage:** All files are private. Short-lived URLs are generated by the server only after owner checks. Object paths begin with `pdf/{user_id}` or `notes/{user_id}`.
- **Cron:** No end-user access; requires a long random `CRON_SECRET` bearer token. Cron is registered once daily and can execute at any minute within the chosen hour on Hobby.

## Current Affairs accuracy

Official source entries preserve original URL, publication date and date precision. PRS monthly issues use month precision; they are not assigned a fictional publication day in the UI. An AI note is generated only from extracted source text (after an explicit button click). Relevance tagging is rule-based and provisional; the user must verify legislation status and dates against the original article.

## Deferred to future version

1. Larger-than-4MB PDF upload with directly signed Storage upload URLs (no Vercel proxy).
2. Scanned PDF OCR with asynchronous processing.
3. Full-page deep extraction and weekly summaries, source provenance and correction workflows.
4. Truly reliable out-of-browser reminders via push or email provider.
5. More granular simultaneous multi-device merging than the current safe conflict-blocking strategy.
6. Calendar-driven rescheduling and AI-generated practice from mistakes.
